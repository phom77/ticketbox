# Design

## Context

A1 authorizes management by organization. A3 projects verified collections into Ticketing independently of settlement. Payment already owns `REDRIVE_QUERY` and late-payment `RECORD_MANUAL_REFUND` review. Notification can retry failed emails. Check-in is the authority for accepted admissions and maintains a local versioned ticket projection.

## Goals and boundaries

Pilot support covers full-order refunds, with manual execution on the approved merchant console. Partial refunds, direct provider refund API calls, financial settlements with organizers and offline admission remain in separate work. An operator reviews used tickets outside the standard workflow until the business defines a policy.

## Decisions

- **Read from the owning service.** Add a separate support search in Ticketing so existing order list callers keep their contracts. Resolve exact normalized email to an account ID via Identity, match transaction references against the local A3 projection, and filter by `orders.organization_id` before paging. Use `created_at DESC, id` and cap page size at 100. Load Payment and Notification summaries separately for a scoped order, using service credentials and redacted DTOs. Show source failure explicitly. Each exception queue can page and retry independently so one service outage preserves access to the others.
- **Reuse current authorization and commands.** Organizer FINANCE grants permit scoped read-only support. Platform commands validate current Identity admin authorization before resolving a case. Reuse query redrive and add a persisted replay identity to Notification's email retry. Audit the actor and action in the source service. A retry schedules at most one delivery for that action. Ambiguous SMTP acknowledgments still require inspection. Approval of a refund requires a different current admin account from the requester. An authorized admin can record the merchant's actual result after approval, including the approver if operationally needed. The app derives the actor from authentication and derives the refundable amount from the verified collection.
- **Hold admission before approving money movement.** Ticketing freezes the exact issued ticket set under its order lock. Check-in requires every expected ID and atomically installs a hold for that set using the same authoritative lock boundary as admission. Prior admission, a transferred ticket or a missing projection blocks approval. The hold persists across projection updates. If the ACK is lost, retry with the same case ID and do not expire the hold automatically. A terminal late-money compensation case with zero issued tickets needs no hold. A settled order whose tickets are missing remains an issuance exception. An audited no-refund decision can release a hold. Confirmed refunds keep the hold in force until revocation is applied, and stale release commands cannot reverse revocation.
- **Record evidence in Payment and apply effects through durable delivery.** Extend the existing review model with a case tied to the verified receipt, immutable actor history and an approval state. Serialize commands by receipt, enforce a unique provider refund reference, allow a single full refund, and keep identical replays stable. Restrict the legacy manual evidence action so it cannot bypass the new approved workflow. Send a versioned confirmed-refund result to Ticketing, leaving the v1 settlement result and ACK intact. Ticketing records a new refund transition under its current order lock, preserves replay, cancels affected valid tickets and emits the existing versioned ticket snapshots. A3 projects the confirmed refund fields, and Notification sends a deduplicated confirmation. Refund application does not restock the sale. Late compensation keeps the original terminal order state.
- **Track disruption as a resumable operation.** Show a preview of affected orders and active attempts, require reason and explicit platform confirmation, and then persist an operation ID. Catalog pauses sales and online admission through the existing outbox. Show each barrier as pending until its owner acknowledges it. Check-in enforces the event admission barrier atomically with admission and retains admission history. For postponement, record the revised schedule and preserve tickets. An explicit resume command can reopen sale and admission at the applicable times after the revised schedule is acknowledged. Cancellation keeps both barriers closed and prepares individual review cases. Pre-pause payment intents can settle until their existing order deadline and are added to the impact set. Ticketing rejects new purchase activity after the pause. Include late receipts in compensation without issuing tickets. Use deduplicated Notification commands keyed by event operation and buyer. Apply the same tracking to the platform emergency route for events with orders.

## Risks and trade-offs

- A synchronous join of all service data would make lookup depend on every service. Independent sections surface missing data and let operators retry the affected source. Missing payment or admission evidence prevents refund approval.
- Partial refunds require allocation and rounding by issued ticket. The pilot records full verified amounts only and retains the policy decision for a later change.
- The software cannot verify a manual merchant-console action independently. A reference, amount, completion time and actor are required, with merchant reconciliation during staging. An ambiguous result keeps the case and admission hold open for operator verification.
- A device disconnected from Check-in may retain an old ticket snapshot. This pilot requires online authority for admission. Device workflow and offline authorization remain in the deferred scanner design.

## Migration and rollout

Add Payment case state, Ticketing refund result inbox and Check-in holds through new migrations. Existing compensation reviews remain visible and completed evidence stays immutable. Deploy consumers before enabling the sender and then expose operator actions after the end-to-end fixture rehearsal. Preserve pending cases and holds on rollback. Disable new commands while allowing delivery of already confirmed cases to finish.
